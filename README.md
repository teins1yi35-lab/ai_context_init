# AI Context Init

AI Context Init 是一个面向 Codex / AI Coding 项目的本地 PowerShell 工具。它在用户明确指定的项目目录中，安全创建一套独立的 AI 上下文文档，让新的 Codex 对话能够恢复项目规则、当前状态、历史决策和交接流程。

项目目录名为 `ai_context_init`。`v0.1.0` 已完成本地提交和标签，当前开发目标为只读审计版本 `v0.2.0`。

## v0.1.0 能做什么

v0.1.0 只做安全初始化，唯一命令参数是必填的 `-TargetPath`。

- `-TargetPath` 必须由用户明确传入，且必须是已经存在的目录。
- `ProjectName` 从规范化后的目标文件夹名称推导，不提供 `-ProjectName`。
- `Goal` 和 `TechStack` 初始值统一写为“待确认”，不提供对应参数，也不扫描项目代码推导。
- 固定处理以下 5 个目标文件：

  ```text
  AGENTS.md
  docs/ai-context/CURRENT_STATE.md
  docs/ai-context/DEV_LOG.md
  docs/ai-context/DECISIONS.md
  docs/ai-context/HANDOFF_PROMPT.md
  ```

- 已有文件逐个跳过，缺失文件继续创建；不会覆盖、删除或改写已有文件。
- 写入前会预检查模板、路径和目标状态；写入使用同目录临时文件和无覆盖原子提升。
- 生成后会检查文件存在性、固定清单、路径范围、编码、空内容、占位符和临时文件残留。
- 不扫描或批量处理 `D:\Codex_work`，不默认操作当前目录。
- 目标项目只接收上下文文档，不复制 `ai_context_init` 的源码、脚本、模板或测试代码。

v0.1.0 不提供或不执行以下能力：

- `-Force`
- `-WhatIf`
- `-ProjectName`、`-Goal`、`-TechStack`
- `validate-ai-context.ps1`（v0.2.0）
- `update-ai-context.ps1`（v0.3.0）
- 自动 Git commit、发布或部署

## v0.2.0 只读校验

`validate-ai-context.ps1` 只审计用户明确指定的已存在目录，不修复、迁移、删除或改写目标项目。它只读取 v0.1.0 固定生成的 5 个上下文文档；清单外文件不会被扫描或报告。

```powershell
# 在 ai_context_init 仓库根目录中运行。
$validator = Join-Path -Path (Get-Location) -ChildPath 'scripts\validate-ai-context.ps1'
$target = 'C:\path\to\an-existing-project'

& powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File $validator `
    -TargetPath $target

$exitCode = $LASTEXITCODE
Write-Output ("ExitCode: {0}" -f $exitCode)
```

每条审计结果包含文件、规则、`Passed` / `Warnings` / `Errors`、简短原因和处理建议，末尾包含各类数量及退出码。仅有 Warning 时退出码仍为 `0`；审计结果写入 stdout，参数错误、路径错误和无法完成审计的读取错误写入 stderr。本版本不提供 JSON 输出。

| 退出码 | 校验含义 | 处理方式 |
| ---: | --- | --- |
| `0` | 审计完成且没有 Errors，允许只有 Warnings | 阅读 Warning 并按建议人工复核 |
| `1` | 参数错误 | 显式传入唯一必填参数 `-TargetPath` |
| `2` | 目标路径错误 | 确认目标存在且为目录 |
| `3` | 审计完成并发现一个或多个 Errors | 按逐项建议人工处理后重新审计 |
| `4` | 读取失败等运行错误，审计无法完成 | 检查文件读取权限或运行环境；不得把本次结果当作通过 |

审计内容包括固定文件存在且非空、UTF-8、Schema Version、文件角色、必要字段、受管理标记、残留占位符和受控状态规则；CURRENT_STATE 明显过长以及 HANDOFF 明确复制动态状态只产生 Warning。额外字段允许存在，Project Name 只检查必要字段是否存在，不强制与目录名匹配。

可用正式隔离矩阵复核校验器。测试每次创建唯一系统临时目录，完成后自动清理，不操作真实项目：

```powershell
& powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File '.\tests\validate-ai-context.matrix.ps1'

& pwsh.exe `
    -NoProfile -ExecutionPolicy Bypass `
    -File '.\tests\validate-ai-context.matrix.ps1'
```

## 环境与脚本位置

目标平台是 Windows PowerShell 5.1 和 PowerShell 7。两个环境均已在隔离临时项目中完成功能验证，PowerShell 7 验证版本为 `7.6.6`。PowerShell 7 的可执行文件路径会随安装方式变化；通用命令使用 `pwsh.exe`。

脚本位置：

```text
scripts\init-ai-context.ps1
scripts\validate-ai-context.ps1
```

## 第一次运行示例

下面的示例只使用隔离的临时测试项目。第一条命令创建测试目录，第二条命令显式把这个已经存在的目录传给 `-TargetPath`。

```powershell
# 在 ai_context_init 仓库根目录中运行。
$toolScript = Join-Path -Path (Get-Location) -ChildPath 'scripts\init-ai-context.ps1'
$target = Join-Path -Path ([System.IO.Path]::GetTempPath()) `
    -ChildPath ('ai-context-init-readme-{0}' -f (Get-Date -Format 'yyyyMMdd-HHmmss'))

if (-not [System.IO.Directory]::Exists($target)) {
    New-Item -ItemType Directory -Path $target -ErrorAction Stop | Out-Null
}

& powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File $toolScript `
    -TargetPath $target

$exitCode = $LASTEXITCODE
Write-Output ("ExitCode: {0}" -f $exitCode)
Get-ChildItem -LiteralPath $target -Recurse -Force
```

脚本成功时，控制台会先显示预检查，再显示最终结果。成功的空目录首次运行通常包含：

```text
WillCreate (5)
Created (5)
Skipped (0)
Warnings (0)
Failed (0)
FinalResult: Success
ExitCode: 0
```

如果再次运行同一命令，5 个文件会出现在 `Skipped` 中，退出码仍为 `0`。PowerShell 中应立即读取 `$LASTEXITCODE`；它表示刚刚调用的脚本进程退出码。

## 生成后的目录结构

```text
目标项目/
├─ AGENTS.md
└─ docs/
   └─ ai-context/
      ├─ CURRENT_STATE.md
      ├─ DEV_LOG.md
      ├─ DECISIONS.md
      └─ HANDOFF_PROMPT.md
```

初始化不会在目标项目创建 `scripts`、`templates`、`tests` 或 `ai_context_init` 源码。

## 结果字段

脚本会输出 `Created`、`Skipped`、`Warnings`、`Failed` 和 `ExitCode`。

| 字段 | 含义 | 常见处理方式 |
| --- | --- | --- |
| `Created` | 本次成功创建的固定目标文件 | 检查生成内容和下一步状态 |
| `Skipped` | 目标文件已存在，本次没有覆盖它 | 保留已有内容；可使用 v0.2.0 只读校验器进行结构审查 |
| `Warnings` | 非致命提醒，例如已有文件被跳过，或并发创建后安全跳过 | 阅读提醒并人工确认已有文件是否符合预期 |
| `Failed` | 失败原因和具体文件或路径 | 根据错误类别和退出码处理；失败时不要把初始化当作成功 |

特别注意：`Skipped` 只表示“未覆盖”，不表示已有文件通过 Schema 校验。v0.1.0 不解析、升级或修复已有文件。

## 退出码与错误处理

| 退出码 | 含义 | 常见提示或处理方式 |
| ---: | --- | --- |
| `0` | 成功，包括部分文件已存在并被跳过 | 查看 `Created`、`Skipped` 和 `Warnings` |
| `1` | 参数错误 | 确认命令中明确写了 `-TargetPath`，且没有依赖当前目录默认值 |
| `2` | 目标路径错误 | 确认路径存在且是目录；不要使用文件、越界路径或 junction/reparse point 路径 |
| `3` | 模板或 Schema 读取失败 | 确认工具目录中的 5 个模板完整、可读、为 UTF-8 无 BOM，且未被修改为未知 Schema/占位符 |
| `4` | 写入失败 | 检查目标目录权限和必要目录占用情况；确认没有留下临时文件后再处理 |
| `5` | 渲染或生成后校验失败 | 查看 `Failed` 中的文件；不要宣称初始化成功，先处理编码、占位符、路径或内容一致性问题 |

常见错误包括：

- 缺少参数：`The required -TargetPath parameter was not provided.`
- 路径不存在：`TargetPath does not exist.`
- 目标是文件：`TargetPath exists but is not a directory.`
- 目标路径包含 junction/reparse point：提示会指出相关路径组件。
- 模板缺失：`A required template is missing or is not a file: ...`
- 模板标记异常：`A template has an invalid or ambiguous Schema/Generated By marker: ...`
- 写入失败：最终结果为 `Failed`，并在 `Failed` 列表中列出具体目标文件和底层错误。
- 生成后校验失败：最终结果为 `Failed`，并列出不合格文件；不会输出成功结果。

脚本不会因为错误自动删除用户已有文件，也不会用覆盖写入来“修复”错误。

## 安全边界

- 只写入显式 `-TargetPath` 下的固定 5 个文档及必要目录。
- 默认不覆盖已有文件；正式写入使用无覆盖语义。
- 不执行来自文本参数的内容，不读取项目业务代码来推导目标信息。
- 不扫描或批量处理 `D:\Codex_work`。
- 不自动提交 Git、不自动发布、不自动部署。
