# 决策记录

本文件记录已确认的重要产品与技术决策。新决策采用递增编号追加；若决策被取代，应保留原记录并注明取代关系，不得删除历史。

## D-001｜项目名与展示名

**决策：** 项目目录名使用 `ai_context_init`，展示名使用 AI Context Init。  
**原因：** 目录名便于本地开发和命令行使用，展示名保持产品可读性。  
**状态：** 已确认。

## D-002｜v0.1.0 只实现安全初始化

**决策：** `v0.1.0` 只实现目标项目上下文文档的安全初始化。  
**原因：** 先验证最小、可预测且默认不覆盖的初始化能力，避免将校验和更新能力提前混入首版。  
**状态：** 已确认。

## D-003｜v0.1.0 只暴露 -TargetPath

**决策：** `v0.1.0` 唯一命令参数为必填的 `-TargetPath`。  
**原因：** 缩小参数面，明确操作目标，降低错误配置和范围膨胀风险。  
**状态：** 已确认。

## D-004｜ProjectName 从目标文件夹名推导

**决策：** `ProjectName` 从规范化后的目标文件夹名称推导，不提供 `-ProjectName`。  
**原因：** 保持项目标识与实际目录一致，减少重复输入和不一致。  
**状态：** 已确认。

## D-005｜Goal 与 TechStack 初始值

## D-014｜退出码规则

**决策：** 成功或仅跳过返回 `0`；参数、路径、模板读取、写入或生成后校验失败返回非 `0`。  
**原因：** 让调用方能够可靠区分成功、无覆盖跳过和实际失败。  
**补充：** PRD 规划参数错误为 `1`、路径错误为 `2`、模板或 Schema 读取失败为 `3`、写入失败为 `4`、生成后校验失败为 `5`。  
**状态：** 已确认。

## D-019｜Schema 1 与占位符白名单

**决策：** 5 个模板统一使用 Context Schema Version `1`；动态占位符白名单只包含 `{{PROJECT_NAME}}` 和 `{{GENERATED_DATE}}`。`Goal` 与 `TechStack` 直接写“待确认”。  
**原因：** `ProjectName` 必须由目标文件夹名推导，Last Updated 需要生成日期；限制占位符数量有利于后续脚本发现未知或未替换占位符并安全失败。  
**状态：** 已确认。

## D-020｜模板更新模式与受管理区块

**决策：** `AGENTS.md` 与 `HANDOFF_PROMPT.md` 使用 `static`，`CURRENT_STATE.md` 使用 `replace`，`DEV_LOG.md` 与 `DECISIONS.md` 使用 `append`；每个模板包含一组文件角色专属、唯一且配对的受管理区块标记。  
**原因：** 更新模式与 PRD 规定的文件职责一致，并为后续结构校验和受控更新预留稳定边界，但当前版本只提供静态模板基础。  
**状态：** 已确认。

## D-021｜显式检查 TargetPath 参数

**决策：** 脚本只声明 `TargetPath`，关闭位置参数绑定，并通过 `$PSBoundParameters` 与空白检查显式确认用户传入 `-TargetPath`；不依赖 Mandatory 参数的交互式提示。  
**原因：** Mandatory 参数在交互式 PowerShell 中可能等待用户输入，显式检查可以在缺失参数时立即输出失败摘要并返回退出码 `1`，同时确保不默认使用当前目录。  
**状态：** 已确认。

## D-022｜写入前完成全部模板与渲染预检查

**决策：** 在创建任何目标目录或正式文件前，先读取固定 5 个模板并完成编码、Schema、Generated By、占位符白名单和渲染结果检查。  
**原因：** 模板缺失、损坏或包含未知占位符时应在零正式写入的状态下停止，避免产生可预防的部分初始化。  
**状态：** 已确认。

## D-023｜正式文件采用 CreateNew 与 UTF-8 无 BOM

**决策：** 正式目标文件使用 `FileMode.CreateNew` 创建，并通过 .NET `UTF8Encoding` 写入 UTF-8 无 BOM；检查后发生并发创建时安全跳过，写入失败时只清理本次调用产生的不完整目标文件。  
**原因：** `CreateNew` 在文件系统层保证不覆盖已有文件，并能处理预检查与正式写入之间的竞态；明确编码对象避免 Windows PowerShell 5.1 与 PowerShell 7 默认编码差异。  
**状态：** 已确认。

## D-024｜同目录临时文件校验后原子无覆盖落盘

**决策：** 初始化缺失文件时，先在正式目标的同一目录使用 `FileMode.CreateNew` 写入唯一临时文件，刷新到磁盘并完成非空、UTF-8 无 BOM、占位符和内容一致性校验，再使用不覆盖的 `File.Move` 将其原子提升为正式文件。目标在提升前被并发创建时，保留并跳过该目标；受控成功、跳过或失败路径均清理本次临时文件。  
**原因：** 避免正式路径在内容尚未完整时可见，同时维持文件系统层的无覆盖竞态保护，并让校验失败在正式落盘前停止。临时文件与正式文件位于同一目录，以避免跨卷移动失去原子性。  
**取代关系：** 本决策细化并部分取代 D-023 中“直接向正式路径使用 `FileMode.CreateNew` 写入”的实现细节；D-023 的 UTF-8 无 BOM、绝不覆盖和失败清理原则继续有效。  

## D-025：v0.2.0 validate-ai-context.ps1 只读审计规则

**决策：** v0.2.0 校验工具仅接受必填 `-TargetPath`，只读取固定 5 个目标文档；默认输出人类可读的 `Passed`、`Warnings`、`Errors` 结果，退出码分别使用 `0`（无 Errors）、`1`（参数）、`2`（路径）、`3`（审计 Errors）和 `4`（读取/运行错误）。不提供 JSON，不写入目标项目。

**原因：** 固定输入和只读边界降低误操作风险；明确区分审计发现的问题与工具无法完成审计的运行错误。

**决策：** 以实际 v0.1.0 模板的 Schema Version、文件角色、必要字段和受管理标记为兼容基线；必要项缺失、冲突或版本不匹配为 Errors，额外字段允许存在。残留占位符和模板定义状态字段中的非法状态词为 Errors。CURRENT_STATE 非空白字符超过 1500 仅为 Warning；UTF-8 BOM 为 Warning，无法 UTF-8 解码为 Error；HANDOFF 只有明确复制 CURRENT_STATE 动态状态时才 Warning，无法可靠判断时不自动结论。

**原因：** 保持与 v0.1.0 生成文档兼容，避免把维护建议或普通叙述示例误判为结构错误；校验工具不修复、不迁移、不扫描清单外文件。

**状态：** 用户已确认，适用于 v0.2.0 阶段 2 实现。
