# AI Context Init v0.1.0 开发计划

本计划只覆盖 `v0.1.0` 的安全初始化。每次只执行当前阶段；上一阶段经用户验收并更新上下文文档后，才进入下一阶段。

## 阶段 1：项目定位与基础文档

### 目标

统一产品定位、版本边界、安全规则、开发阶段与项目自身的上下文维护机制。

### 产物

- `README.md`
- `AGENTS.md`
- `docs/PLAN.md`
- `docs/ai-context/CURRENT_STATE.md`
- `docs/ai-context/DEV_LOG.md`
- `docs/ai-context/DECISIONS.md`
- `docs/ai-context/HANDOFF_PROMPT.md`

### 验收标准

- 产品名、项目目录名和版本边界与 PRD 一致。
- 明确 v0.1.0 只做安全初始化，唯一参数为 `-TargetPath`。
- 文档之间不存在规则冲突。
- 所有未知或未验证内容如实标为“待确认”或“未测试”。
- 未创建 `scripts`、`templates` 或 `tests`，未编写任何脚本、模板或测试代码。

## 阶段 2：模板文件设计

### 目标

设计 5 个目标上下文文档的 `.template` 文件，为一致初始化和后续 Schema 校验预留稳定结构。

### 产物

- `AGENTS.md.template`
- `CURRENT_STATE.md.template`
- `DEV_LOG.md.template`
- `DECISIONS.md.template`
- `HANDOFF_PROMPT.md.template`
- 模板字段、白名单占位符、静态 Schema Version 与受管理区块约定

### 验收标准

- 5 个模板职责清晰、内容互不冲突。
- `ProjectName` 占位值可由目标文件夹名填充。
- `Goal` 与 `TechStack` 初始值固定为“待确认”。
- 字段、标记和占位符通过人工审查。
- 模板中不包含目标项目不应获得的工具源码或测试代码。

## 阶段 3：编写 init-ai-context.ps1

### 目标

实现 v0.1.0 初始化主流程，并严格限制参数面、目标路径和文件清单。

### 产物

- `scripts/init-ai-context.ps1`
- 参数、路径、模板和目标文件预检查
- 模板渲染、逐文件跳过、结果汇总与退出码

### 验收标准

- 唯一参数为必填 `-TargetPath`。
- 不默认使用当前目录，不扫描 `D:\Codex_work`。
- `ProjectName` 从目标文件夹名推导，`Goal` 与 `TechStack` 写“待确认”。
- 不实现 `-Force`、`-WhatIf`、`-ProjectName`、`-Goal` 或 `-TechStack`。
- 只处理固定的 5 个目标上下文文件及必要目录。
- 核心路径、模板渲染和写入流程可运行。

## 阶段 4：使用临时测试项目进行人工验证

### 目标

在与真实项目隔离的临时目录中验证初始化行为，不修改其他项目。

### 产物

- 人工验证记录
- 实际执行命令、环境、结果和发现的问题

### 验收标准

- 覆盖空目录首次创建。
- 覆盖重复运行时全部跳过且内容不变。
- 覆盖部分文件存在时逐个跳过、继续创建缺失文件。
- 覆盖中文路径和空格路径。
- 覆盖 Windows PowerShell 5.1 与 PowerShell 7，若环境缺失必须如实记录“未测试”。
- 验证目标目录外文件修改数为 0。

## 阶段 5：完善路径校验、防覆盖、原子写入和生成后校验

### 目标

强化 v0.1.0 的安全写入机制，使错误、竞态和半写入场景按规则停止。

### 产物

- 规范化路径与目录类型校验
- 无覆盖创建和并发竞态处理
- 临时文件与原子落盘策略
- 文件非空、编码、残留占位符和清单外写入校验
- 对应退出码与错误结果

### 验收标准

- 路径不存在、不是目录或越界时零写入并返回规定的非 0 退出码。
- 已有文件内容和时间戳不被修改。
- 并发创建时绝不覆盖目标文件。
- 写入失败不留下半截正式文件或无说明临时文件。
- 生成后校验失败时不得宣称初始化成功。

## 阶段 6：完善参数、错误提示和使用说明

### 目标

让用户能够根据文档独立、安全地执行 v0.1.0，并理解所有结果与失败原因。

### 产物

- 完整的 `README.md` 使用说明
- 参数说明、示例、结果解释和错误处理建议
- `Created`、`Skipped`、`Failed`、`Warnings` 和退出码说明

### 验收标准

- 使用说明只包含实际存在且已验证的命令。
- 明确 `Skipped` 不代表已有文件通过 Schema 校验。
- 所有错误提示能定位参数、路径、模板、写入或校验问题。
- 新用户可按说明在明确的临时或目标目录中完成操作。

## 阶段 7：Git 初始化、版本提交和 v0.1.0 发布准备

### 目标

在用户明确授权下完成版本管理与发布前检查，准备 `v0.1.0`。

### 产物

- Git 仓库与版本提交（仅在用户明确授权后）
- `CHANGELOG` 或等价发布说明
- `v0.1.0` 发布检查清单与标签准备
- 双 PowerShell 环境最终验证记录

### 验收标准

- Windows PowerShell 5.1 和 PowerShell 7 的核心用例均有真实验证记录。
- 发布物不包含密钥、token、个人数据、日志、备份或无关文件。
- 范围未越过安全初始化，不包含后续版本能力。
- 用户验收并明确授权后才提交、打标签或发布。
- 不自动部署。

## 建议增强项

Pester 自动化测试可作为 `v0.1.0` 的建议增强项，优先覆盖首次创建、重复运行、部分文件存在和错误路径；完整 Pester 套件不是第一版必做范围。是否在 `v0.1.0` 发布前加入，由后续阶段依据风险和实际进展确认。

## 后续版本路线

- `v0.2.0`：实现 `validate-ai-context.ps1`，进行只读结构检查、Schema、标记、占位符和文件职责审计。
- `v0.3.0`：实现 `update-ai-context.ps1`，使用结构化输入、证据字段、受管理区块、追加规则和 diff 完成受控更新。

上述两个脚本不进入 `v0.1.0` 的实现或验收范围。
