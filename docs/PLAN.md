# AI Context Init v0.1.0 开发计划

本计划只覆盖 `v0.1.0` 的安全初始化。每次只执行当前阶段；上一阶段经用户验收并更新上下文文档后，才进入下一阶段。

## 阶段 1：项目定位与基础文档

### 目标

统一产品定位、版本边界、安全规则、开发阶段与项目自身的上下文维护机制。

### 产物

- `README.md`
- `AGENTS.md`
- `docs/PLAN.md`
- `docs/ai-context/CURRENT_STATE.md`
- `docs/ai-context/DEV_LOG.md`
- `docs/ai-context/DECISIONS.md`
- `docs/ai-context/HANDOFF_PROMPT.md`

### 验收标准

- 产品名、项目目录名和版本边界与 PRD 一致。
- 明确 v0.1.0 只做安全初始化，唯一参数为 `-TargetPath`。
- 文档之间不存在规则冲突。
- 所有未知或未验证内容如实标为“待确认”或“未测试”。
- 未创建 `scripts`、`templates` 或 `tests`，未编写任何脚本、模板或测试代码。

## 阶段 2：模板文件设计

### 目标

设计 5 个目标上下文文档的 `.template` 文件，为一致初始化和后续 Schema 校验预留稳定结构。

### 产物

- `AGENTS.md.template`
- `CURRENT_STATE.md.template`
- `DEV_LOG.md.template`
- `DECISIONS.md.template`
- `HANDOFF_PROMPT.md.template`
- 模板字段、白名单占位符、静态 Schema Version 与受管理区块约定

### 验收标准

- 5 个模板职责清晰、内容互不冲突。
- `ProjectName` 占位值可由目标文件夹名填充。
- `Goal` 与 `TechStack` 初始值固定为“待确认”。
- 字段、标记和占位符通过人工审查。
- 模板中不包含目标项目不应获得的工具源码或测试代码。

## 阶段 3：编写 init-ai-context.ps1

### 目标

实现 v0.1.0 初始化主流程，并严格限制参数面、目标路径和文件清单。

### 产物

- `scripts/init-ai-context.ps1`
- 参数、路径、模板和目标文件预检查
- 模板渲染、逐文件跳过、结果汇总与退出码

### 验收标准

- 唯一参数为必填 `-TargetPath`。
- 不默认使用当前目录，不扫描 `D:\Codex_work`。
- `ProjectName` 从目标文件夹名推导，`Goal` 与 `TechStack` 写“待确认”。
- 不实现 `-Force`、`-WhatIf`、`-ProjectName`、`-Goal` 或 `-TechStack`。
- 只处理固定的 5 个目标上下文文件及必要目录。
- 核心路径、模板渲染和写入流程可运行。

## 阶段 4：使用临时测试项目进行人工验证

### 目标

在与真实项目隔离的临时目录中验证初始化行为，不修改其他项目。

### 产物

- 人工验证记录
- 实际执行命令、环境、结果和发现的问题

### 验收标准

- 覆盖空目录首次创建。
- 覆盖重复运行时全部跳过且内容不变。
- 覆盖部分文件存在时逐个跳过、继续创建缺失文件。
- 覆盖中文路径和空格路径。
- 覆盖 Windows PowerShell 5.1 与 PowerShell 7，若环境缺失必须如实记录“未测试”。
- 验证目标目录外文件修改数为 0。

## 阶段 5：完善路径校验、防覆盖、原子写入和生成后校验

### 目标

强化 v0.1.0 的安全写入机制，使错误、竞态和半写入场景按规则停止。

### 产物

- 规范化路径与目录类型校验
- 无覆盖创建和并发竞态处理
- 临时文件与原子落盘策略
- 文件非空、编码、残留占位符和清单外写入校验
- 对应退出码与错误结果

### 验收标准

- 路径不存在、不是目录或越界时零写入并返回规定的非 0 退出码。
- 已有文件内容和时间戳不被修改。
- 并发创建时绝不覆盖目标文件。
- 写入失败不留下半截正式文件或无说明临时文件。
- 生成后校验失败时不得宣称初始化成功。

## 阶段 6：完善参数、错误提示和使用说明

### 目标

让用户能够根据文档独立、安全地执行 v0.1.0，并理解所有结果与失败原因。

### 产物

- 完整的 `README.md` 使用说明
- 参数说明、示例、结果解释和错误处理建议
- `Created`、`Skipped`、`Failed`、`Warnings` 和退出码说明

### 验收标准

- 使用说明只包含实际存在且已验证的命令。
- 明确 `Skipped` 不代表已有文件通过 Schema 校验。
- 所有错误提示能定位参数、路径、模板、写入或校验问题。
- 新用户可按说明在明确的临时或目标目录中完成操作。

## 阶段 7：Git 初始化、版本提交和 v0.1.0 发布准备

### 目标

在用户明确授权下完成版本管理与发布前检查，准备 `v0.1.0`。

### 产物

- Git 仓库与版本提交（仅在用户明确授权后）
- `CHANGELOG` 或等价发布说明
- `v0.1.0` 发布检查清单与标签准备
- 双 PowerShell 环境最终验证记录

### 验收标准

- Windows PowerShell 5.1 和 PowerShell 7 的核心用例均有真实验证记录。
- 发布物不包含密钥、token、个人数据、日志、备份或无关文件。
- 范围未越过安全初始化，不包含后续版本能力。
- 用户验收并明确授权后才提交、打标签或发布。
- 不自动部署。

## 建议增强项

Pester 自动化测试可作为 `v0.1.0` 的建议增强项，优先覆盖首次创建、重复运行、部分文件存在和错误路径；完整 Pester 套件不是第一版必做范围。是否在 `v0.1.0` 发布前加入，由后续阶段依据风险和实际进展确认。

## 后续版本路线

- `v0.2.0`：实现 `validate-ai-context.ps1`，进行只读结构检查、Schema、标记、占位符和文件职责审计。
- `v0.3.0`：实现 `update-ai-context.ps1`，使用结构化输入、证据字段、受管理区块、追加规则和 diff 完成受控更新。

上述两个脚本不进入 `v0.1.0` 的实现或验收范围。

## v0.2.0 阶段计划：校验与审计

v0.2.0 只覆盖对目标项目既有上下文文档的只读检查。本节记录方案和实现阶段；每个阶段均须用户验收后才能进入下一阶段。

### v0.2.0 阶段 1：校验工具方案设计（已验收）

目标：依据 PRD FR-VAL-01 至 FR-VAL-06 和实际 Schema 1 模板，冻结或标记待确认的校验边界、结果模型、验证矩阵与安全约束。

产物：

- 本节的 v0.2.0 分阶段计划。
- 校验规则设计：文件完整性、Schema 元数据、文件角色、必要字段、受管理标记、内容规则和长度规则。
- 只读审计输入、`Passed` / `Warnings` / `Errors` 输出模型与处理建议。
- 隔离样本验证矩阵；每项明确零写入要求。
- 与 v0.1.0 生成文档的兼容性核对记录。

验收标准：

- 规则能映射到 FR-VAL-01 至 FR-VAL-06，并区分 PRD 已明确内容与待确认方案。
- 不编写校验脚本，不修改目标项目文件，不实现自动修复、迁移或 v0.3.0 更新。
- 明确校验工具只读，任何样本失败都验证目标文件零写入。

### v0.2.0 阶段 2：校验脚本实现（已验收）

目标：在阶段 1 验收后实现 `validate-ai-context.ps1`，只读取用户明确指定的单一目标项目并输出审计结果。

范围：实现用户已确认的输入参数、固定 5 文件清单、Schema/字段/标记/内容规则、结果格式和退出码；不扩展到自动修复、迁移或 v0.3.0 更新。

验收：Windows PowerShell 5.1 和 PowerShell 7 均需在隔离样本中验证，覆盖正常、错误和 Warning 样本；所有用例只读且目标文件哈希、长度和时间戳不变。

### v0.2.0 阶段 3：人工验证与边界复核（已验收）

目标：使用隔离样本覆盖通过、警告、错误、版本不匹配和内容损坏场景，核对输出可理解、零写入和跨 PowerShell 版本一致性。

验收：完成验证矩阵，记录命令、环境、退出码、输出摘要和样本文件变化；发现规则冲突时先暂停并更新方案，不自动修复样本。

### v0.2.0 阶段 4：发布准备（已验收）

目标：在用户验收阶段 2/3 后整理 README/CHANGELOG、双环境证据和发布候选内容。

边界：不实现 v0.3.0 `update-ai-context.ps1`，不自动修复、迁移、改写或提交目标文档。

## v0.2.0 阶段 1 校验规则设计

以下规则以当前 5 个 Schema 1 模板的实际字段为基线；“建议”表示方案，未得到用户确认前不是冻结决策。

### 文件完整性与只读边界（FR-VAL-01、FR-VAL-05）

- 固定检查 5 个文件：`AGENTS.md`、`docs/ai-context/CURRENT_STATE.md`、`docs/ai-context/DEV_LOG.md`、`docs/ai-context/DECISIONS.md`、`docs/ai-context/HANDOFF_PROMPT.md`。
- 每个文件必须存在且非空；缺失或空文件进入审计结果，不创建替代文件、不写回、不格式化。
- 目标目录外路径、`scripts`、`templates`、`tests` 和工具源码不属于校验输入清单。
- 建议输入为显式单一目标路径；参数名称、是否必须、是否允许相对路径以及不存在路径的退出码均待确认。

### Schema、文件角色与必要字段（FR-VAL-02）

当前模板共同要求一次且可解析的：

- `Context Schema Version: 1`
- `Generated By: ai_context_init v0.1.0`
- `Project Name: ...`
- `File Role: ...`
- `Last Updated: YYYY-MM-DD`
- `Update Mode: static | replace | append`

按文件角色建议检查：

- `AGENTS.md`：`stable_project_rules`，包含 `ProjectName`、`Goal`、`TechStack` 和证据/状态规则。
- `CURRENT_STATE.md`：`current_project_state`，包含 `ProjectName`、`Goal`、`TechStack`、当前状态和验证状态。
- `DEV_LOG.md`：`append_only_development_log`，包含初始化记录和状态词。
- `DECISIONS.md`：`append_only_decisions`，角色与受管理区块正确；空的受管理区块在 v0.1.0 初始文档中是允许的。
- `HANDOFF_PROMPT.md`：`conversation_handoff`，包含固定接续流程和状态规则，不应复制 CURRENT_STATE 的动态状态。

必要字段的精确集合、字段重复时的严重级别、`Generated By` 是否必须锁定为 v0.1.0、日期格式容忍度和未知额外字段处理方式均待确认。

### 受管理标记（FR-VAL-03）

- 每个文件必须存在其文件角色对应的一组 `<!-- AI_CONTEXT:<ROLE>:START -->` 与 `<!-- AI_CONTEXT:<ROLE>:END -->`。
- START 和 END 必须各出现一次，START 必须位于 END 之前，不能交叉、嵌套或出现未配对标记。
- 标记角色必须与文件角色对应；缺失、重复、顺序错误、角色错误或跨文件标记均报告问题。
- 校验只读标记和内容，不移动、补写或删除标记。

### 内容规则（FR-VAL-04）

- 残留占位符：检测 `{{...}}`；未知或未替换占位符报告问题，具体是 `Warning` 还是 `Error` 待确认。
- 状态词：允许集合建议为 `planned`、`in_progress`、`completed`、`verified`、`accepted`、`blocked`、`to_confirm`、`not_tested`；状态字段出现其他词报告非法状态。是否扫描所有自然语言中的反引号词，还是只扫描已知状态字段，待确认。
- CURRENT_STATE 长度：检查是否为空以及是否超出 PRD/文档约定长度；具体单位、上下限和超限严重级别待确认，不能直接把建议长度写成冻结规则。
- HANDOFF 重复状态：检查 HANDOFF 是否重复承载 CURRENT_STATE 的动态状态，或在固定接续说明中重复出现状态字段；“重复”的精确定义和严重级别待确认。

### 审计结果与退出码（FR-VAL-05、FR-VAL-06）

建议输出结构：

- `TargetPath`、工具/Schema 版本和固定文件清单摘要。
- `Passed`：通过的文件或规则。
- `Warnings`：不阻断审计但需要人工确认的风险。
- `Errors`：缺失、空文件、Schema/角色/字段/标记/内容规则失败。
- 每条问题包含文件相对路径、规则编号、实际值摘要、建议处理方式；不包含自动修复动作。

建议处理方式是“先备份或查看 Git diff，再由用户或后续受控工具处理”；校验工具本身不得写回目标文档。

`Passed` / `Warnings` / `Errors` 的确切文本格式、是否输出 JSON、输出到 stdout/stderr、参数名称、退出码数值和 Warning 是否影响退出码，PRD 均未冻结，全部列为待确认方案。不得在实现前把这些项目写成已确认决策。

### 隔离样本验证矩阵

每个样本均使用独立临时目录，先记录 5 个目标文件的 SHA-256、长度和最后写入时间，运行审计后再次比较；所有用例的零写入判定为三项均不变且无新增文件。

| 样本 | 变更 | 预期覆盖规则 | 零写入要求 |
| --- | --- | --- | --- |
| 完整 v0.1.0 输出 | 直接使用 5 个模板生成的完整文档 | FR-VAL-01 至 06 全部 | 5 个文件不变 |
| 缺失文件 | 删除或不创建其中 1 个文件 | FR-VAL-01 | 不创建缺失文件 |
| 空文件 | 将其中 1 个文件截断为空 | FR-VAL-01 | 空文件保持为空 |
| 标记缺失 | 删除 START 或 END | FR-VAL-03 | 不补写标记 |
| 标记重复 | 重复 START 或 END | FR-VAL-03 | 不去重 |
| 标记顺序/角色错误 | 交换顺序或改角色名 | FR-VAL-03 | 不重排、不改名 |
| 残留占位符 | 加入 `{{UNRESOLVED}}` | FR-VAL-04 | 不替换占位符 |
| 非法状态词 | 将已知状态字段改为未允许词 | FR-VAL-04 | 不改状态 |
| CURRENT_STATE 长度异常 | 构造过短和超长样本 | FR-VAL-04 | 不截断、不扩展 |
| HANDOFF 重复状态 | 复制 CURRENT_STATE 动态状态到 HANDOFF | FR-VAL-04 | 不删除重复内容 |
| Schema 版本不匹配 | 将 `Context Schema Version: 1` 改为其他版本 | FR-VAL-02 | 不迁移版本 |
| 角色/必要字段不匹配 | 删除或改写角色/字段 | FR-VAL-02 | 不补字段 |

阶段 1 只设计该矩阵；实际运行属于 v0.2.0 后续验证阶段，当前未测试。

## v0.2.0 阶段 1 待确认项

- 校验工具的正式参数名、是否必须显式传入目标路径、相对路径和不存在路径行为。
- `Passed` / `Warnings` / `Errors` 的精确输出格式、是否提供 JSON 和 stdout/stderr 分流。
- 退出码数值、Warning 是否导致非零退出，以及参数/路径错误与内容审计错误的区分。
- 必要字段的精确清单、额外字段处理、Generated By/Schema 版本是否严格锁定。
- CURRENT_STATE 长度的单位、上下限与严重级别。
- HANDOFF “重复状态”的判定范围与严重级别。
- 残留占位符和非法状态词的严重级别。
- 是否检查 UTF-8 编码、BOM、Project Name 与目录名一致性，以及目标目录清单外文件；这些属于增强建议，需单独确认是否进入 v0.2.0。
